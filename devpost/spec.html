🔍 Catch the AI: Technical Spec

The blueprint: two pieces, two AI jobs, and everything else plain code.

In plain language

The webpage shows the 4 screens and runs the game. One serverless function on Vercel keeps the secret Groq key and does two jobs: make the case (notes → summary + 3 fair mistakes + saved facts, as JSON) and check the fix (answer vs. saved fact → correct / close / wrong). Counting, scoring and labels are plain code, so they're always exactly right.

DIVI MIND lessons built in: notes are the only source of truth, and JSON instead of free text (no stray **).

🎯 Your learning focus: the instructions to Groq

These live in api/_prompts.js. Each rule fixes a real problem.

Make the case (when Learn is clicked)
  1. Use ONLY the student's notes. No outside facts. ← fixes DIVI's “Karnataka CM” problem
  2. 4–6 points, 1–2 short sentences each, key terms in a bold list, plain text with no markdown symbols. ← fixes raw **
  3. Exactly 3 sentences, in 3 different points, made wrong.
  4. Fair: each one clearly contradicts a specific fact in the notes. No tricks, tiny wording changes, or debatable claims.
  5. For each mistake, save correct_fact, topic, and nudge.
  6. For every sentence, give why (one line).
Check the fix (each correction)
  1. Compare only with the saved correct fact, not with general knowledge.
  2. Judge meaning, not wording.
  3. correct = states the key idea · close = partly right · wrong = contradicts, repeats the mistake, or is unrelated.
How you'll test them during the build
  • Sample notes + one set of your own B.Com notes → are the 3 mistakes fair?
  • “demand goes down” → correct · “demand stays the same” → wrong · a half answer → close
  • If something's off, you decide which rule to tighten.

Temperature 0.2: the AI's “creativity” dial, turned down for consistent answers.

Case data (what Groq sends back)

{
  "points": [ { "sentences": [
      { "text": "When price rises, quantity demanded falls.",
        "bold": ["price", "quantity demanded"],
        "why":  "Your notes say demand moves opposite to price." } ] } ],
  "mistakes": [
    { "point": 0, "sentence": 0,
      "wrong_text":   "When price rises, quantity demanded also rises.",
      "correct_fact": "When price rises, quantity demanded falls.",
      "topic": "how price affects demand",
      "nudge": "Think about what happens to demand when price goes up." } ]
}

Kept in the webpage's memory only. Refresh or Next case → gone. Your choice: peeking is possible, but “cheating only cheats yourself.”

More details

⚠️ Where it could break, and what the user sees
  • Broken AI output: validate, retry once, then “Our detective got confused 🕵️ Try again”
  • Groq slow or down: “Investigating your notes… 🔍,” then a friendly retry. No error codes.
  • Unfair mistake: caught by testing two sets of notes, then tighten the instructions
  • Judging too strict or too loose: the four known test answers, then adjust the instructions
✂️ Simplified on purpose
  • Answers kept in the webpage (your choice), no database, no login, no framework
  • One AI call makes the whole case: faster, and Catch always matches Learn
  • Hand-made confetti; built-in sample notes (labelled). The kernel is never faked.
